Keep this checklist updated in the implementation commit that completes a task.

TARGET FLOW

failed command + execution context
    -> shell parser / AST
    -> resolve the app and its installed native completion handler
    -> identify suspicious token(s)
    -> collect candidates from:
         completion candidates (from the app itself; primary source)
         shell history
         filesystem
         CLI --help
         man pages
         program-specific plugin
         stderr parser
    -> candidate ranking
    -> safety analysis
    -> suggest / execute through the user's shell

Stderr diagnosis also feeds suspicious-token detection before candidate
collection. Safety policy applies to discovery probes as well as execution;
the final candidate safety gate remains after ranking.

CORE REQUIREMENT: THE INSTALLED APP OWNS ITS COMMAND KNOWLEDGE

Detect the actual executable and ask that app's native completer what is
valid at the affected token position. For example, aws routes to AWS CLI
completion, gcloud to Google Cloud CLI completion, and az to Azure CLI
completion. Their adapters handle invocation and response formats; notypo
must not maintain copies of their services, commands, flags, or resource lists.
This requirement applies to every provider and tool in the inventory below,
as well as unlisted apps discovered through a supported completion protocol.

Cover the entire command surface exposed by the installed app: nested groups,
operations, flags, enum values, positional arguments, installed extensions,
and dynamic resource values when supported by the app and discovery policy.
The same mechanism must support other CLIs with native completion handlers.
CLI upgrades and extension changes must be reflected without a notypo release.

History, filesystem, help, man pages, and stderr supply context and fallback
evidence. They cannot substitute a stale command catalog for an available
native completer. Program-specific plugins are protocol bridges and diagnostic
adapters, rather than independently maintained application implementations.

Completion is used to repair a failed command, not merely complete its final
word. Query the diagnosed token inside its command context and rank the app's
valid alternatives. Metadata discovery must not execute the failed operation.

5A. CLOUD PROVIDER AND CLI INVENTORY

Each entry is a NOT DONE integration/verification task, not a claim that
completion support is implemented. For each listed executable, discover and
invoke its installed completion handler, verify the exposed command surface,
add regression fixtures, and document any actual capability limits. A CLI
without native completion must report that fact and use current app-supplied
help/metadata as the existing fallback, rather than inventing a command catalog.

The inventory identifies apps and test targets. It must not become a dispatch
allowlist, duplicated cloud API schema, or list of hand-coded command fixes.
Nested services/commands/plugins are discovered from the app, not enumerated
here. Recheck executable names, lifecycle, and native interfaces against the
installed version; a provider can introduce another CLI after this inventory.

IMPLEMENTATION ORDER

First slice: contracts + failure context + simple POSIX AST + app identification
            + native completion discovery/protocols + centralized probes
            + aws/gcloud/az bridges + token diagnosis + ranking + safety + UI.
            Keep this slice behind the opt-in setting. App-native correction
            is part of this first slice rather than a later optional feature.
Second slice: metadata/cache freshness + history/filesystem/stderr support
             + shared native protocols + section 5A provider/client coverage
             + help/man fallback + git bridge + enabled resource completion.
Third slice: broader shell syntax/dialects + additional native protocols
             + upgrade/extension coverage + default-engine rollout.
Add relevant acceptance tests with each slice; testing and safety are not
deferred until all providers exist. All seven requested candidate sources
must be integrated before this plan is marked complete.
